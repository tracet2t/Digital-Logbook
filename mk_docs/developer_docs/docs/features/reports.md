# Reports

Reports summarize mentor activity and student progress over a time period. They can be exported for record-keeping or sharing with stakeholders.

---

## Overview

Reports are generated by **mentors** and can be reviewed by **admins**. Because generating a report can take time (querying and processing data), it's done **asynchronously** in a background queue.

**Route:** `/mentor/reports` (mentor) and `/admin/reports` (admin)  
**Access:** Mentor and Super Admin  
**Key Components:**
- `server/src/app/admin/reports/page.tsx`
- `server/src/components/reports/ReportsTable.tsx`

---

## What's in a Report?

A report typically includes:

| Section | Description |
|---|---|
| **Mentor Info** | Name and ID of the mentor who generated the report |
| **Date Range** | The period the report covers |
| **Student Activity** | Summary of logged activities per student |
| **Feedback Summary** | Breakdown of approved/rejected/pending activities |
| **Time Analysis** | Total and average hours logged |

---

## Report Statuses

| Status | Meaning |
|---|---|
| `pending` | Queued, not started yet |
| `wip` | Currently being generated |
| `completed` | Ready to view/download |
| `error` | Generation failed |

---

## How to Generate a Report

1. Go to **Mentor Dashboard → Reports** (or **Admin → Reports**)
2. Click **"Generate Report"**
3. Select the **date range** (optional — defaults to the current month)
4. Click **"Generate"**

The report will appear in the list with a `pending` or `wip` status. Refresh the page after a few moments — once the status shows `completed`, the report is ready.

!!! tip "Reports are async"
    Report generation happens in a background queue (BullMQ + Redis), so the page won't freeze while it's being built.
    See [Special Logic](../special-logic.md) for technical details.

---

## Export Options

Once a report is `completed`, it can be:

- **Viewed** in the browser
- **Downloaded** as a **CSV** file

PDF export support is planned for future versions.

---

## How It Works Technically

```
Mentor clicks "Generate"
        │
        ▼
POST /api/reports → job added to BullMQ queue
        │
        ▼
Background worker generates the report
        │
        ▼
Report saved in Reports table (status: completed)
        │
        ▼
Mentor/Admin sees completed report in the list
```
